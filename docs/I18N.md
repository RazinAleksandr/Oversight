# Localization (English + Русский)

The Director owns this document. If something here is unclear or wrong, report it; don't improvise a different convention.

## 1. How it works

- **Keys are the English strings themselves.** English needs no dictionary. Russian lives in `src/i18n/ru/`:
  - `content/<id>.ts`: display strings of data modules (`src/content/**`, `src/engine/data/*`, `src/engine/labels.ts`), one dictionary file per source file.
  - `engine.ts`: keys of `t()`/`tp()`/`tr()` calls in `src/engine/**`.
  - `ui.ts`: keys of `t()`/`tp()`/`tr()` calls in `src/ui/**`, `src/art/**`, `src/fx/**` and `src/*.tsx`.
  - `index.ts` assembles the pack. It is generated; never edit it.
- **The language is fixed for the page lifetime.** At boot, `main.tsx` reads the setting and calls `setLang('ru', pack)` (the pack is lazy-loaded), then `localizeContent()` (`src/engine/localize.ts`). Only after that does it import the rest of the app. Switching language in Settings saves the setting and reloads the page. Because of this boot order, module-level `t()` calls are fine.
- **Static data objects** (content modules, `engine/data/*`, `engine/labels.ts`) are translated *in place* by `localizeContent()`. Their source must stay plain English literals; never wrap them in `t()`.
- **Strings produced inside content functions** are translated by the engine at the sink with `tr()`:
  - `requires` disabled-reason strings;
  - `h.log`, `h.news`, `h.meter`/`h.risk` reasons;
  - `h.text` templates.

  `fillTemplate()` also calls `tr()` on its template.
- **API** (`src/i18n/index.ts`):
  - `t('Quarterly income')`
  - `t('Falling behind {rival}', { rival: r.name })`
  - `tp(n, '{n} action', '{n} actions')`: the Russian value has 3 forms separated by `|`: `"{n} действие|{n} действия|{n} действий"`
  - `tr(str)`: lookup only, no params
  - `listJoinL(items)`: "A, B и C"
  - `locale()`: `'ru-RU'` | `'en-US'`
  - `getLang()`
- **Tooling:**
  - `npx tsx scripts/i18n.ts sync --only <id>` regenerates key skeletons and keeps existing translations. Only run it for files you own.
  - `npx tsx scripts/i18n.ts check [--only <id>]` reports missing translations and placeholder errors.
  - `npx tsx scripts/i18n.ts list` lists the dictionary file ids.

## 2. Dictionary file format (translators)

```ts
export const forms: FormsTable = { "Атлантическая Федерация": { gen: "Атлантической Федерации", prep: "Атлантической Федерации" } };
const dict: Record<string, string> = {
  "English key — never edit": "Русский перевод",
};
export default dict;
```

- **Never change a key.** Only fill in the value. An empty value means "not translated".
- Values are JSON strings. Escape `"` as `\"`, and prefer «ёлочки» so you rarely need to escape. Keep `\n` if the key has one.
- **Placeholders** `{token}` must be kept. You may move them, give them a case form (`{country:gen}`), or swap equivalent tokens (`{countryAdj}` → `{country:gen}`). Never invent a token that doesn't exist.
- A string that is a pure brand name (company, model, lab) stays identical; copy it as the value.

## 3. Tokens and Russian grammar

`{token}` inserts the value as displayed in the UI (nominative, capitalized as a name). `{token:form}` inserts a grammatical form: `nom` (nominative as written mid-sentence, e.g. lowercase), `gen`, `dat`, `acc`, `ins`, `prep`. If a form is missing, the nominative value is used, so **phrase sentences so that the nominative also reads acceptably.**

| Token | Value (ru) | Declines? | Advice |
|---|---|---|---|
| `{country}` | «Атлантическая Федерация» | yes (forms) | «правительство {country:gen}», «в {country:prep}» |
| `{countryShort}` | «Атлантика» | yes | |
| `{countryAdj}` / `{rivalAdj}` | (adjective) | **avoid** | rephrase: "the Atlantic government" → «правительство {country:gen}» |
| `{capital}` | «Конкорд» | yes | |
| `{leader}`, `{leaderShort}` | «Маркус Делейни» | rarely provided | keep in nominative: «— заявляет {leaderTitle} {leader}» |
| `{leaderTitle}` / `{rivalLeaderTitle}` | «Президент», «Канцлер» | yes | `{leaderTitle:gen}` etc.; `nom` gives lowercase «президент» |
| `{company}`, `{model}`, `{rivalLab}` | Latin brands (Halcyon Labs, Vega-3) | **no** | «компания {company}», «модель {model}», «лаборатория {rivalLab}» |
| `{ceo}`, `{scientist}`, `{economist}`, `{chiefOfStaff}`, `{spymaster}` | Cyrillic person names | rarely | keep in nominative |
| `{rival}` | country name | yes | «{rival:gen}», «с {rival:ins}» |
| `{sector}` | «Бизнес», «Госуслуги», «Инфраструктура», «Оборона» | yes, forms are lowercase | «в {sector:prep}», «для {sector:gen}» |
| `{situation}` | threat name | yes | `{situation:nom}` mid-sentence |
| `{policy}` | law name | yes | «закон «{policy}»» is safest (nominative in quotes) |
| `{year}`, `{quarter}`, `{date}` | 2028, «3 кв.», «3 кв. 2028» | no | |

**Who provides forms** (in the `forms` export of their own dictionary file):

- **content-countries:** country names, short names, capitals and leader titles.
- **engine-labels:** sector names.
- **content-situations:** situation names (`name` and `unknownName`).
- **engine-data-policies:** law names.
- **engine.ts:** fallback token values (e.g. «иностранная держава»).

## 4. Style

- **Register:** a political thriller told through government dossiers. Dry, precise and bureaucratic, with tension underneath. Natural Russian, never a word-for-word calque. Prefer shorter phrasing.
- **Address** the player formally and in lowercase: «вы», «ваш».
- **Typography:**
  - quotes «…» (nested „…“);
  - em dash « — » with spaces; en dash for ranges «4–7»;
  - use **ё** consistently;
  - non-breaking concerns are handled by CSS; don't insert NBSP.
- **Length:** choice labels should stay as short as the English (≤ ~50 characters). Button and tab labels should be 1–2 words.
- **Numbers** stay as in the source; don't convert units or currencies inside text. "$40 billion" becomes «40 млрд долларов».
- **Abbreviations:** AI → **ИИ**. AGI → «ОИИ». GPU → GPU. Keep "red team" as «ред-тиминг» / «красная команда».
- **Names:**
  - Companies, labs, AI models and products stay in **Latin script** unchanged.
  - People are transliterated into Cyrillic (practical transcription): Marcus Delaney → Маркус Делейни, Dr. → «д-р», Gen. (ret.) → «ген. в отставке».
  - Media outlets are translated (see §5).

## 7. Rules for code agents (engine / UI)

- Wrap **every player-visible string literal** in code: `t('...')`, including template literals (``` `Falling behind ${x}` ``` → `t('Falling behind {rival}', { rival: x })`). Use named params, never positional.
- **Don't wrap:**
  - ids, CSS classes, keys, log/debug messages, `console.*` output;
  - dev-only pages and `src/ui/mock.ts`;
  - static objects in `engine/data/*` and `engine/labels.ts` (they are walked).
- Prefer whole sentences as keys over concatenated fragments: Russian word order differs. Never build a sentence from translated pieces when one key with params would do.
- **Plurals** always use `tp()`. The English helpers that add "s" must go.
- **Dates and numbers:** use `locale()` for `toLocaleString`/`Intl`. Quarter labels go through `dateLabel()`, which uses `t('Q{q} {year}')`; ru gives «{q} кв. {year}».
- Never compare a display string for logic. Compare ids.
- After wrapping, run `npx tsx scripts/i18n.ts sync --only engine` (or `--only ui`) and translate the values in your dictionary.
- English output must stay byte-identical: tests and the balance sim run in English.
